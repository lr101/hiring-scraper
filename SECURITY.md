# Security policy

## Supported versions

Security fixes target `main` and the most recent stable release, once releases are
published. Older versions do not receive dedicated backports. Use the current
release and review its changelog for migration requirements.

## Reporting a vulnerability

Do not post exploit details, credentials, CVs, or personal data in public issues
or pull requests. Use GitHub's
[Report a vulnerability](https://github.com/lr101/hiring-scraper/security/advisories/new)
option when private vulnerability reporting is enabled.

If that option is unavailable, contact the
[maintainer](https://github.com/lr101) through a private contact method listed on
their profile. If no private method is listed, open an issue asking only for a
private security contact, without vulnerability details. Maintainers should enable
private reporting as described in [the maintainer checklist](docs/maintaining.md).

Include the affected version or commit, reproduction steps using sanitized data,
impact, and any suggested mitigation. Allow maintainers time to investigate and
coordinate a fix before publishing details. This project is maintained on a
voluntary basis and does not promise a response deadline or bounty.
