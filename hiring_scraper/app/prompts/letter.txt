Task: write a cover letter for the specific work in the posting. The application fills in
sender, recipient, date, salutation, sign-off and signature.

Output contract
- EXAMPLE SLOTS contains original evidence grouped by employer or institution. Select the
  best two or three distinct slots for the core duties. Each slot takes one paragraph or
  null. Set priority 1 for the most relevant paragraph and number the rest in reading order.
  Give each selected slot an anchor from the single entry described in that paragraph.
- Write each example as linked sentences. Assign every sentence one source that verifies
  the exact action, collaborator and outcome stated. Use job only for a sentence about
  the posting or an explicitly future contribution. Use the slot's supplemental facts
  only when they concern the chosen entry. If no single source supports the complete
  sentence, split or narrow it. The application joins the sentences and retains their ids.
- Use motivation for interest and fit for an optional future contribution or a verified
  language clause. Keep past work in the example slots. Set fit.uses_language_level only
  when the fit paragraph includes a level explicitly requested by the posting and verified
  by EVIDENCE. Use fit=null when it adds no distinct point. Use at most four body
  paragraphs including motivation and fit; use fewer when evidence is sparse.

Structure
- Write three body paragraphs and a short closing by default. Add a fourth body paragraph
  when a core requirement otherwise lacks a verified example. Aim for 270–310 words in
  English or 260–320 in German, including the closing.
- Motivation: connect a duty stated in the posting to a concrete verified capability.
  State interest directly and warmly in the applicant's voice; use the company's name in the
  opening and, if natural, in the closing. Ground any description of the employer in the
  posting. Save the past action, collaborators and result for the example paragraph.
- Examples: choose and order examples strictly by the posting's core duties. In each
  experience or education paragraph, name one core duty and connect it to the closest
  verified example:
  - For a software or SaaS product role, prefer verified software platform development,
    collaboration with developers on technical feasibility and iterative/agile delivery,
    KPI/data work paired with a verified operational result (such as an onboarding-time
    reduction), and research-to-prototype work over unrelated physical-product concepts.
    If iterative delivery is central, name the verified method and the applicant's actual
    collaboration with developers.
  - For a hardware or industrial product role, prefer verified CAD/BOM/costing work,
    market or benchmark analysis, and partner or customer collaboration. Use verified
    external collaboration for a core partnership duty, keeping the actual partner type
    and nature of the collaboration. A short verified example involving an adjacent
    partner type is useful evidence for this duty.
  Where the evidence links feedback or analysis to a choice, explain what it helped the
  applicant or team decide. Where the source gives only an action and purpose, use those.
  Name the discipline for study examples. Keep each paragraph to three or four sentences.
- Mention a verified level only if the posting explicitly requires that language. Use one
  short, natural clause about communication or collaboration that the level supports. Keep
  any past collaboration at its documented scope, including which language was used if
  known. Keep the clause out of sentences about unrelated duties or outcomes.
- Closing: invite a personal conversation or interview in one warm, concise sentence.
  Name a concrete topic from the role that the applicant wants to discuss. A thank-you is
  optional. Introduce no new claims or qualifications.

Check the final draft before returning it
- Give each paragraph a different duty or argument. Merge sentences that restate the same
  point. Avoid recycling an action/object phrase or the same bridge verb across examples.
  Compose in fresh first-person prose from the evidence; do not quote source sentences.
- Formula and rhythm checks:
  - Use at most ONE forward-looking conditional formula ("würde ich …" / "I would bring …" /
    "I would apply …") in the ENTIRE letter; use indicative, varied constructions everywhere
    else.
  - Never end two body paragraphs with the same closing construction or bridge formula (do
    not repeat replacement formulas like "I am keen to …" across paragraphs either), and
    reserve "I look forward to" / "Ich freue mich auf" for the closing sentence only so no
    phrase repeats between a body paragraph and the closing.
  - Once the connection to the role is clear, land the paragraph on a verified action,
    outcome or specific question. A stock sentence about transferring the experience
    adds little, especially when another paragraph already makes the connection.
  - Never start three or more consecutive sentences with "I <verb>" or the same opening
    pattern; vary openings by leading with context, purpose, tools, collaborators or outcomes.
  - In English, use "KPIs" rather than "performance indicators".
- Audit every past-tense clause and every statement about the applicant's usual practice
  against cited evidence. Keep tracking, analyzing, proposing and deciding distinct.
  Match leadership scope, stage and results exactly. Where the evidence stops short of
  the posting duty, say what the applicant wants to do or learn in the new role.
  Use one independently verifiable action and its documented outcome per sentence.
  Skip a detail if saying what was measured, improved or decided would require guessing.
  Check causal links too: when evidence supports two
  contributions separately, write them as independent actions. Do not imply one produced or
  informed the other unless the source says so. Do not claim unsupported tenure, releases,
  or decisions. Use job as the source of sentences about the posting and future plans.
- Spell out English contractions. In German, keep formal Sie-Form throughout ("Sie"/"Ihr",
  matching the voice notes) and start lowercase after the comma-ended salutation unless the
  first word is a noun, proper name or formal Sie/Ihr.

Use "Application for <job title>" in the English subject. Use the role in the German subject,
with a reference number only if the posting explicitly provides it.
In "contact_name", copy the name explicitly identified as the vacancy contact, without titles
or honorifics. In English, use the first name alone if that is all the posting gives. In German,
return a full name only. Return an empty string for an email-only or unnamed contact. Do not
use a name mentioned only as a colleague or inferred from an email address.
